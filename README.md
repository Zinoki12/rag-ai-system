# rag-ai-system

Семантический поиск и вопрос-ответ по markdown-базе знаний (Obsidian-совместимой).
Postgres + pgvector хранит индекс, эмбеддинги и генерация подключаются
взаимозаменяемо — облачным API или локальной моделью.

## Как это устроено

Это **библиотека** (как `net/http`: вы её вызываете, она вас не вызывает), плюс
три бинаря — тонкие обёртки над ней.

```go
kb, err := knowledge.Open(ctx, knowledge.Config{...})
defer kb.Close()

kb.Index(ctx)                  // vault/*.md → notes → chunks → векторы
kb.Search(ctx, "вопрос", 5)    // вопрос → вектор → top-k
kb.Ask(ctx, "вопрос", 5)       // + промпт → ответ со ссылками на источники
```

Подробности и примеры — [docs/usage.md](docs/usage.md).

| Публичный пакет | Что это |
|---|---|
| `knowledge` | вся система: `Open`, `Index`, `Search`, `Ask`, `Stats` |
| `embed` | **коннектор эмбеддингов**: `Provider` + google/ollama/fake, ретраи, лимитер |
| `llm` | **коннектор генерации**: `Provider` + google/ollama/stub |
| `rag` | сборка промпта, без зависимостей от БД и провайдеров |
| `backoff` | политика ретраев, общая для обоих коннекторов |

Под `internal/` — детали реализации, не контракт: `vault` (обход каталога и
frontmatter), `chunk` (нарезка по абзацам), `storage` (Postgres), `migrate`
(goose, миграции вшиты в бинарь), `httpapi`, `config`.

### Пространства эмбеддингов

Векторы разных моделей несравнимы: косинус между ними вычисляется без ошибок и
означает ничего. Поэтому каждое сочетание (провайдер, модель, размерность) —
отдельное **пространство** со своей физической таблицей и своим hnsw-индексом,
зарегистрированное в `embedding_spaces`.

Практические следствия:

- Размерность живёт в типе колонки, поэтому смена модели не требует `ALTER TABLE`.
- Старые векторы продолжают обслуживать запросы всё время миграции.
- Смешать два пространства в одном `ORDER BY <=>` структурно невозможно.
- Откат на прежнюю модель = вернуть переменные окружения. Пересчёта нет.

Стадия эмбеддинга ищет работу запросом «у каких чанков нет вектора в этом
пространстве», а не «какие заметки только что записали». Поэтому смена модели
запускает полный пересчёт сама, а прерванный прогон продолжается с места
остановки.

## Запуск

```bash
cp .env.example .env          # заполнить POSTGRES_*, VAULT_PATH
docker compose up -d
docker compose exec ollama ollama pull nomic-embed-text
```

Индексация и поиск:

```bash
go run ./cmd/ingest
go run ./cmd/ask -search "как устроен чанкинг"    # только поиск, без модели
go run ./cmd/ask "как устроен чанкинг"            # ответ + источники
```

Переключение на облачный провайдер — без единой правки кода:

```bash
GOOGLE_API_KEY=... EMBED_PROVIDER=google EMBED_MODEL=gemini-embedding-001 \
  go run ./cmd/ingest
```

Полностью локальная генерация:

```bash
docker compose exec ollama ollama pull llama3.2
LLM_PROVIDER=ollama LLM_MODEL=llama3.2 go run ./cmd/ask "как устроен чанкинг"
```

Заголовок «Показано модели» вместо «Источники» — намеренно. Это фрагменты,
которые попали в промпт; утверждать, что ответ опирается именно на них,
программа не может, и на вопрос вне базы модель честно отвечает «в базе знаний
нет ответа», а список остаётся непустым. Рядом печатается лучшая косинусная
близость: порога релевантности пока нет — он зависит от модели и корпуса, и
подбирать его по тестовому vault из пяти заметок значило бы подгонять
константу под фикстуру.

HTTP:

```bash
go run ./cmd/server
curl -s localhost:8081/health
curl -s -XPOST localhost:8081/search -d '{"query":"чанкинг","k":5}'
curl -s -XPOST localhost:8081/ask    -d '{"question":"как устроен чанкинг"}'
curl -s -XPOST localhost:8081/reindex          # 202, индексация в фоне
curl -s localhost:8081/reindex/status
```

## Проверки

```bash
go build ./... && go vet ./... && go test -race ./...
```

Тесты не требуют ни сети, ни ключей: провайдеры `fake` и `stub` закрывают весь
путь офлайн, HTTP-слой тестируется через подставной `Service`.

## Схема БД

Миграции лежат в `internal/migrate/migrations` и вшиты в бинарь через
`//go:embed`; накатываются при старте любой команды под advisory-локом.
Отдельного шага «применить схему» нет, и правка `docker-entrypoint-initdb.d`
больше ни на что не влияет — этот каталог срабатывал только на пустом волюме.
