# Подключение стороннего приложения к rag-ai-system

Документ для тех, кто строит приложение поверх этой базы знаний — например
«Журнал надзора» в отдельном модуле.

## Что доступно снаружи

```
module github.com/Zinoki12/rag-ai-system
```

Весь содержательный код лежит под `internal/`, а Go запрещает импортировать
такие пакеты из другого модуля. Пакеты `cmd/*` — это `package main`, их нельзя
импортировать в принципе.

**Следствие: Go-API наружу нет.** Точек подключения ровно две — HTTP и каталог
vault. Это следствие того, что репозиторий строился как приложение, а не как
библиотека, и менять это стоит только осознанно (см. ниже).

### Вариант А: HTTP (рекомендуемый по умолчанию)

```
GET  /health   покрытие индекса и активное пространство эмбеддингов
POST /search   {"query": "...", "k": 5}     → ранжированные чанки
POST /ask      {"question": "...", "k": 5}  → ответ + источники + top_score
```

Нулевая связность по коду, независимый деплой, приложение может быть хоть не на
Go. Цена — сеть между своими же сервисами и отсутствие типов на границе.

`sources` — это заметки, которые попали в промпт, а **не** утверждение о том, на
что опёрся ответ: на вопрос вне базы модель честно ответит «в базе знаний нет
ответа», а список останется непустым. `top_score` — косинусная близость лучшего
фрагмента, по ней потребитель может судить сам. Порога релевантности нет
намеренно: он зависит от модели и корпуса.

### Вариант Б: вынести пакеты из `internal/`

Поднять `embed`, `llm`, `rag`, `backoff` на уровень модуля — тогда они
импортируются как обычная библиотека. Это превращает их в публичное API:
изменение сигнатуры после этого ломает чужой билд. Делать только когда контракт
устоялся.

`storage` и `app` наружу выносить не стоит — они завязаны на конкретную схему.

### Вариант В: общий vault

Приложение пишет markdown, rag-ai-system его индексирует. Связности по коду нет
вообще. Само по себе поиска не даёт, но нужно в любом случае, если источник
данных — чужая база.

**На практике В и А работают вместе:** приложение пишет заметки в vault, а
читает результаты по HTTP.

## Контракт заметки в vault

Индексируются файлы `*.md` (регистр расширения неважен), рекурсивно от
`VAULT_PATH`. Из фронтматтера сейчас читается **только `title`** — см.
`internal/vault/parser.go`. Всё остальное молча отбрасывается, в базу не
попадает и для фильтрации недоступно.

Frontmatter должен начинаться с `---` на первой значимой строке и закрываться
`---`. Незакрытый блок — предупреждение, файл пропускается, остальной прогон
продолжается.

### Требования к пишущей стороне

- **Писать атомарно**: временный файл + `os.Rename`. Индексатор читает файл
  целиком через `os.ReadFile` без блокировок и может поймать половину записи.
- **Идемпотентность до байта**: одинаковый вход обязан давать одинаковый файл.
  Заметка переиндексируется по несовпадению sha256; если в файл попадает время
  генерации или порядок ключей плавает, каждый прогон будет пересчитывать все
  чанки и все векторы вхолостую.
- **Удаление пока не поддерживается**: `cmd/ingest` добавляет и обновляет
  заметки, но не удаляет те, что исчезли из vault.

## Схема базы

`notes` → `chunks` → одна таблица векторов на каждое пространство эмбеддингов,
плюс реестр `embedding_spaces`. Схемой владеет goose, миграции вшиты в бинарь.

**Если стороннее приложение возьмёт ту же базу** и тоже будет использовать
goose, таблица версий у обоих по умолчанию называется `goose_db_version` и
миграции подерутся. Лечится `goose.SetTableName("<своё имя>")` на стороне
приложения. Чище — держать для приложения отдельную базу, а эту оставить
производным индексом, который можно снести и перестроить.

## Чего пока нет

Список известных ограничений, если приложение на них наткнётся:

1. **Нет эндпоинта переиндексации.** Записали заметку в vault — она не попадёт в
   поиск, пока кто-то не запустит `cmd/ingest`. Нужен `POST /reindex`, желательно
   фоновой задачей плюс `GET /reindex/status`: синхронный запрос будет висеть
   весь прогон.
2. **Метаданные фронтматтера не сохраняются** (кроме `title`), поэтому
   фильтрованный поиск — «только по этому объекту», «только за август» — сегодня
   невозможен. Потребует парсера на `yaml.v3`, колонок или JSONB в `notes` и
   `WHERE` в `storage.Search`.
3. **Поиск без фильтров**: `Search` возвращает top-k по всему корпусу, без
   разделения на арендаторов.
4. **HTTP без аутентификации.** Пока слушает `127.0.0.1` — терпимо; при выходе
   наружу нужен хотя бы статический токен.
5. **Вложения не индексируются**: пайплайн текстовый, фотографии он не видит.
