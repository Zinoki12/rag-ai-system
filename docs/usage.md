# Как этим пользоваться

Репозиторий — **библиотека** в том же смысле, что `net/http`: вы её вызываете,
она вас не вызывает, не заводит горутин, о которых вы не просили, и не трогает
сигналы. Три бинаря в `cmd/` — тонкие обёртки над той же библиотекой, а не
что-то отдельное.

## Быстрый старт: библиотека

```go
import (
    "github.com/Zinoki12/rag-ai-system/embed"
    "github.com/Zinoki12/rag-ai-system/knowledge"
    "github.com/Zinoki12/rag-ai-system/llm"
)

kb, err := knowledge.Open(ctx, knowledge.Config{
    Postgres: knowledge.Postgres{
        Host: "127.0.0.1", Port: "5433",
        User: "rag", Password: "secret", Database: "ragdb",
    },
    VaultPath: "/srv/vault",
    Embedder:  embed.Config{Provider: embed.ProviderOllama},
    Generator: &llm.Config{Provider: llm.ProviderOllama, Model: "llama3.2"},
})
if err != nil { return err }
defer kb.Close()

res, err := kb.Index(ctx)                        // проиндексировать vault
hits, err := kb.Search(ctx, "вопрос", 5)         // семантический поиск
answer, err := kb.Ask(ctx, "вопрос", 5)          // ответ + источники
stats, err := kb.Stats(ctx)                      // покрытие индекса
```

`Open` подключается, накатывает миграции, поднимает провайдеры и регистрирует
пространство эмбеддингов. Всё остальное — методы с контекстом.

**`Postgres` вместо `DSN` — не вкусовщина.** Собрать строку подключения руками
легко неправильно: пароль с `@`, `/`, `#` или `%` обязан быть
percent-encoded, а почти правильный DSN падает с ошибкой про URL-escape, а не
про слэш в пароле. Я сам наступил на это, когда писал пробный потребитель.
`DSN` остаётся для тех, у кого строка уже есть готовая.

`Generator: nil` даёт базу только для поиска: `Ask` вернёт
`knowledge.ErrNoGenerator`, а `Index` и `Search` работают как обычно. Это
правильный режим для индексатора — отсутствующая или сломанная настройка модели
не должна ронять индексацию.

`Logger: nil` означает молчание: библиотека не пишет в stdout без спроса.

Компилируемые примеры — `knowledge/example_test.go` и `embed/example_test.go`.
У них нет `// Output:`, поэтому Go их собирает, но не выполняет: базы и модели
для запуска нет, а вот разойтись с API они не могут.

## Публичные пакеты

| Пакет | Что это |
|---|---|
| `knowledge` | вся система: `Open`, `Index`, `Search`, `Ask`, `Stats` |
| `embed` | коннектор эмбеддингов: `Provider`, google/ollama/fake, ретраи, лимитер |
| `llm` | коннектор генерации: `Provider`, google/ollama/stub |
| `rag` | сборка промпта; без зависимостей от БД и провайдеров |
| `backoff` | политика ретраев, общая для обоих коннекторов |

Под `internal/` остались детали реализации: обход vault, чанкинг, доступ к
Postgres, миграции, HTTP-слой. Их специально не видно снаружи — это не контракт,
и менять их можно свободно. Если что-то из них понадобится наружу, это отдельное
решение, а не случайность.

### Коннекторы отдельно от всего остального

`embed` и `llm` ни от чего в этом репозитории не зависят и не требуют базы:

```go
provider, err := embed.New(ctx, embed.Config{
    Provider: embed.ProviderGoogle,   // или ProviderOllama, или ProviderFake
    Model:    "gemini-embedding-001",
    Dim:      768,
    APIKey:   os.Getenv("GOOGLE_API_KEY"),
})
vectors, err := embed.Batched(ctx, provider, texts, embed.KindDocument)
```

Ретраи с backoff и рейт-лимит уже навешаны фабрикой. `Batched` режет вход по
лимиту батча конкретного провайдера и сохраняет порядок.

**`Kind` — параметр, а не настройка**, и это сделано нарочно. Модели размещают
документ и поисковый запрос в разных местах пространства; перепутать их — тихая
просадка качества выдачи без единой ошибки в логах. В сигнатуре забыть нельзя.

## Пространства эмбеддингов

Векторы разных моделей несравнимы: косинус между ними считается без ошибок и
означает ничего. Поэтому каждое сочетание (провайдер, модель, размерность) —
отдельное **пространство** со своей таблицей и своим hnsw-индексом.

Следствия, на которые можно рассчитывать:

- Смена модели не требует `ALTER TABLE` — размерность живёт в типе колонки.
- Старые векторы продолжают обслуживать запросы всё время миграции.
- Смешать два пространства в одном поиске структурно невозможно.
- Откат на прежнюю модель = вернуть настройку. Пересчёта нет, проверено.

`Index` ищет работу вопросом «у каких чанков нет вектора в этом пространстве»,
а не «какие заметки только что записали». Поэтому смена модели запускает полный
пересчёт сама, прерванный прогон продолжается с места остановки, а вызывать
`Index` часто — дёшево.

## Что должна гарантировать пишущая в vault сторона

Если ваше приложение генерирует markdown (например, проектор из базы данных):

- **Писать атомарно**: временный файл + `os.Rename`. Индексатор читает файл
  целиком, без блокировок, и может поймать половину записи.
- **Одинаковый вход → байт в байт одинаковый файл.** Переиндексация идёт по
  sha256 файла. Если туда попадёт время генерации или поплывёт порядок ключей,
  каждый прогон будет вхолостую пересчитывать все чанки и все векторы.
- Удалять файл при удалении сущности — `Index` уберёт заметку из индекса
  вместе с чанками и векторами.

Из фронтматтера сейчас читается **только `title`**. Остальные поля (`kind`,
`entity_id`, `tags`, `relation_ids`) в базу не попадают, поэтому фильтрованный
поиск — «только по этому объекту», «только за август» — пока невозможен.

## HTTP вместо библиотеки

Если приложение не на Go или нужен отдельный процесс:

```
GET  /health          покрытие индекса и активное пространство
POST /search          {"query": "...", "k": 5}
POST /ask             {"question": "...", "k": 5}
POST /reindex         запускает индексацию в фоне → 202
GET  /reindex/status  состояние текущего или последнего прогона
```

`/reindex` отвечает 202, а не 200: работа принята, а не выполнена. Индексация
обходит каталог и может сотни раз сходить к модели — синхронный эндпоинт держал
бы соединение весь прогон и отваливался бы по таймауту на любом реальном vault.
Повторный запрос во время прогона получает 409 и статус текущего, а не ставит
второй проход в очередь.

`sources` в ответе `/ask` — это заметки, которые попали в промпт, а **не**
утверждение о том, на что опёрся ответ: на вопрос вне базы модель честно скажет
«в базе знаний нет ответа», а список останется непустым. Рядом `top_score` —
близость лучшего фрагмента; порога релевантности нет намеренно, он зависит от
модели и корпуса.

## Общая база данных

Схемой владеет goose, миграции вшиты в бинарь и накатываются в `Open` под
advisory-локом. Если ваше приложение возьмёт **ту же** базу и тоже будет
использовать goose, таблица версий у обоих по умолчанию `goose_db_version` и
миграции подерутся — лечится `goose.SetTableName` на вашей стороне. Чище держать
для приложения отдельную базу, а эту оставить производным индексом, который
можно снести и перестроить.

`Config.SkipMigrate` отключает накат, если схемой управляют снаружи.

## Чего пока нет

- **Аутентификации на HTTP.** Пока слушает `127.0.0.1` — терпимо; при выходе
  наружу нужен хотя бы статический токен. `/reindex` при этом изменяет данные.
- **Метаданных фронтматтера в базе** (кроме `title`) и, как следствие,
  фильтров в поиске.
- **Индексации вложений**: пайплайн текстовый, фотографии он не видит.
